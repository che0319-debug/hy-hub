## UI 規劃與風格 A

主要工作：讓 HY 看懂誰能領新包，調整未來新包的路由與門檻；看既有包為何改派。
唯一重點是頁首「設定僅影響之後建立的新包」，採既有 `.hy-card.is-focus`。
使用 hy-ui 的卡片、按鈕、狀態 pill、欄位列表及 disclosure；不新增儀表板、額度頁、
圖表、排行或模型 API。路由列與表單只補必要的響應式排版，顏色與字級沿用 tokens。

| 畫面順序 | 1280px | 390px |
| --- | --- | --- |
| 生效界線與權限 | 頁首重點卡 | 最前方重點卡 |
| 路由表 | 角色、主端／備援、動作三欄 | 每列角色、派工、動作依序向下 |
| 門檻編輯 | 雙欄表單 | 單欄，點選範圍至少 44px |

這張表取代 ASCII 線框，以符合本次溝通格式要求。

## 功能與權限

- 「專家團 → 執行者與模型」新增全域、owner、專案角色／類型與範圍預設覆寫。
  保留原文件內其他範圍的規則，恢復繼承也先成為草稿。
- 顯示六層解析順序；預覽呼叫既有後端 preview，回傳實際繼承來源。
  不在瀏覽器另建一套正式路由解析器。
- 依後端配置列出相容 runner。未就緒不可選；已綁定仍標示「待實際驗收」。
  自訂獨立 GPT reviewer 必須先由後端建立可信配置，不接受任意發明的名稱。
- 編輯 N、時間窗口、min_samples、未領門檻／連續數、兩個比率門檻、冷卻、
  auto_reassign_enabled 與轉派上限。前端做相同數值範圍防呆，後端仍是唯一驗證權威。
- owner-only 保存需要原因、授權依據、明示「僅影響新包」，PUT 攜帶 expected_revision。
  409 保留草稿、禁止再覆蓋；需確認捨棄草稿並重新讀取最新版本。401 處理登入過期，
  403 顯示本人限制。delegate 只讀，不顯示編輯與保存動作。
- 專案執行計畫的覆寫與來源預設收合、按需單次讀取；切換現有專案分頁保留未儲存草稿。
  草稿離開頁面有瀏覽器提醒；重新讀取路由前需確認丟棄未儲存內容。
- 包詳情保留凍結 r 版本、契約 lane、目前派工版本、主端冷卻／事件原因、樣本不足與
  現行政策差異。沒有「改派」「重設」「遷移」「核准合併」或 tick 按鈕。
- 工作日誌增加只讀的冷卻／恢復／改派事件，展示舊／新端、政策與派工版本、
  指標、門檻、冷卻、理由及授權來源。既有 Router notes 標為系統，不冒充 HY 發言。
- 舊制模型回報保留在獨立收合區，只供既有專案；不把舊排程當成新 Router 的就緒證明。
