# 950157 AI 甘特圖 MVP（獨立運作）

## 畫面規劃與風格 A 自評

主要工作：在同一張總表查看、編輯多專案排程及三種查核點。唯一重點是可直接操作的總表；頁首訊息清楚顯示尚未儲存、已儲存或錯誤。

沿用既有 950157 頁首與分頁，新增第四個「AI 甘特圖」。沿用 hy-ui token、hy-btn、既有狀態文字；表格、時間條、菱形與編輯 dialog 是排程必要元件。依使用者明確規格，負責人色使用固定身分雜湊，主專案共用品牌色；綠／紅／黑菱形為規格類型，不作為工作狀態色。

自評：已檢查 1280px／390px。原有風格、單一焦點、錯誤與空資料狀態、44px 手機操作、表格列對齊、無頁面外層橫向溢位均通過。第一輪截圖後縮窄手機凍結名稱欄、加入週日期刻度，再重新截圖。

## 功能與操作

- 新增主專案；選取任一專案或工作，再新增子工作、查核點。
- 名稱、負責人、日期可直接編輯。「編輯／階層」可改父層，連同整個子樹重新歸屬專案，禁止循環與掛在查核點之下。
- ↑／↓ 調整同層順序。▸／▾ 展開收合，支援任意深度；測試超過 1,000 層，呈現縮排有上限以保留可讀寬度，資料階層沒有三層限制。
- 刪除前顯示名稱及含子項的筆數並確認。
- 主專案起訖自動取所有子工作與查核點的日期範圍，空專案顯示 —。
- 時間條中央拖曳平移，左右把手改起訖；菱形可拖曳。以天為單位吸附，日期不會反轉。鍵盤左右鍵平移、Alt＋左右鍵改開始日、Shift＋左右鍵改結束日。
- 月檢視顯示 93 天、週檢視顯示 28 天，可改時間起點及切換前後期間。所有專案始終同表，沒有單專案切換。
- 明確按「儲存甘特圖」持久化。讀取失敗禁止編輯與儲存；409 保留本機變更，可先匯出 JSON，再重新讀取核對；儲存中禁止編輯，離開前對未儲存內容警示。
- 原有頁首儲存／重新整理按鈕在甘特圖分頁會轉用甘特圖流程，避免誤寫進度資料；其他分頁維持原流程。

## 資料與邊界

僅使用 `GET /api/950157-gantt`、`PUT /api/950157-gantt`，沿用 Bearer 登入。資料為 `{revision, items}`，專用檔案 `gantt/950157.json`。版本衝突拒絕寫入，不自動合併。

任一項目含 id、project_id、parent_id、order、kind、name、owner、start、end、status、checkpoint_type、date。主專案日期為衍生值，不另存。沒有進度百分比、歷史版本介面或任何業務整合。JSON 匯出僅為衝突時保留未儲存變更；本階段沒有匯入／自動合併功能。

實務保護上限：每張總表 5,000 筆，日期範圍 1900–2200，階層深度不設固定上限。儲存沿用既有 hy-data GitHub Contents API，沒有新增 DB、LLM 或背景排程。正式資料未被建立或修改。

## 驗收修訂

依使用者回饋，移除表格與編輯視窗的狀態欄。既有資料的 status 僅為儲存契約相容而原樣保留，日期紅字依使用者標記，不以今天日期自動判斷。依本輪確認先完成桌面手動版，AI 文字修改與手機版優化暫緩。delay 依使用者 Excel 習慣，以結束日紅字呈現；開始日紅字表示已開始執行。

## 日期紅字規則（使用者定義）

在「編輯／階層」勾選「已開始執行」後，開始日變紅字；勾選「delay／已延後」後，結束日變紅字，項目名稱也變紅字。兩個標記可分別取消，會隨甘特圖儲存、重讀，不以日曆日期自行推定。主專案與工作都可標記，查核點仍只有日期與三種規格菱形。沒有恢復狀態欄，也沒有原訂底條、斜線、延後天數或歷史版本。時間條仍依負責人色，其他主專案仍同色，三種查核點色不變。

## A+ 三層展開（2026-11-17）

A+ 是主專案 `aplus`，預設連同五條線一起收合，只佔一列，並顯示下一個節點（子孫查核點裡日期 ≥ 今天、最早的一筆；今天用 Asia/Taipei）。展開狀態只在這次瀏覽的記憶體，不寫回、不進 localStorage。其他專案仍預設全展開。

點 A+ 出現五條線。線上的查核點帶 `inline: true`（id 為 `aplus-ms-*`，或掛在 `aplus-line-1`～`5` 底下）時畫在該線的時間條上，不另開一列；既有專案的查核點仍是獨立列。再點一條線才看到週任務。第 833 列「123」不匯入。展品線起日是 2026-11-09，避免切掉「袖套 BLE 開發板韌體環境建置」；A+ 總列仍由子項算出 2026-10-19～2028-09-30。

檢視新增「全期」，刻度為月，範圍涵蓋目前可見列。預設仍是「月」（93 天），「週」仍是 28 天。時間軸在可見範圍內畫今天直線。手機（640px 以下）用 CSS 隱藏負責人、開始日、結束日，表頭節點仍在，只留序次與項目，時間軸留在表格內捲動。

A+ 總列與五條線的顏色只跟穩定 id 走，不改主專案品牌色與負責人雜湊。正式 API 目前只接受既有欄位與 `started`、`delayed`，不接受 `inline`。`docs/quality/gantt/aplus-items.json` 仍保留 `inline` 標記，`scripts/merge-aplus-gantt.mjs` 合併輸出時拿掉它，畫面改認 id。腳本不呼叫網路。這次沒有寫入正式甘特資料。

## GUI 可編輯改版（2026-11-23，規格 v1.1）

畫面上可直接編輯後自動儲存（短 debounce，走 `PATCH /api/950157-gantt` 差異寫入）。仍保留「儲存甘特圖」與衝突時的「匯出變更」。409 會提示重新整理，不會默默蓋掉。

完成狀態只有未完成／完成（列上的打勾）。勾選時先確認「這列會從甘特永久刪除，不會進封存，月報之後也查不到」；確認後立即從畫面與資料集移除，沒有封存區，也沒有等待天數。手動刪除同樣是確認後永久刪除，並提示子列筆數。「復原上一步」只救得回剛剛那一動（含誤勾完成或誤刪）。

名稱紅字改為：今天（Asia/Taipei）已超過結束日（查核點比對其日期）且該列仍在（即未完成）。不再使用手動「已開始執行／delay」勾選作為顯示依據；編輯框已拿掉這兩個勾選。舊資料裡的 `started`／`delayed` 仍可隨存檔保留，但畫面忽略它們。這與 11/17 文件「手動勾已延後才紅字」不同，是這次規格變更。

父列若是工作（`kind=task`），子列改日期時結束日會自動延伸到不早於子列最晚結束日。主專案起迄仍由子項計算，不寫進主專案列。工具列新增「新增同層」。

全期刻度的一月改為 `2027/01`（不再寫成 `27/1`）。全期時工具列顯示起訖年月，並提供「跳到期末」，手機不靠猜測也能捲到 2028。`?tab=gantt` 已在 `950157-dashboard.html` 用與週覆盤／研究相同的同步切頁；模組載入後的 click 仍保留作後援。

誰能改：後端仍是「已登入即可寫入」。現行登入無法分辨使用者、950157、Tiffany，未做前端假權限。修改紀錄顯示「已登入使用者」。
