# 系統阻塞呈現規劃

主要工作：讓 HY 看懂審查為何停住，以及該由誰處理。唯一重點為專案頁的系統異常摘要；保留既有待你決定卡片位置，不把系統通知放入待決數。

沿用 hy-card、hy-pill bad、hy-kv、hy-note；不增加色彩或核准按鈕。手機保留原待決事項在前，阻塞摘要在專案標題之後；會議室通知純文字，無可按動作。

| 畫面 | 桌面與手機排列 |
|---|---|
| 專案 | 既有標題 → 系統阻塞：原因／起算／負責人／期限標示 → 原分頁內容 |
| 正式卡片 | 原標題 → 阻塞原因 → 原有可用動作（未通過獨立審查不可核准） |
| 會議室 | 改派或異常通知摘要，無核准鈕 → 既有對話 |

狀態、期限皆來自後端；「因系統阻塞順延」為標示，不自行改寫已核准日期。未知錯誤保留原文；已知錯誤顯示具體原因與下一步。
